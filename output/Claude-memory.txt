Key learnings & principles

IP protection via Supabase dependency: All agent system prompts, R7 compression rules, and image style prompts live in Supabase behind auth. A pirated binary without valid credentials is non-functional. Zero code fallbacks — degrading gracefully would expose the IP.
SYSTEM CONTEXT block stays hardcoded in Cochi (contains dynamic workspace.path and permissionLabel); Supabase serves only static content. R9 accumulator stays in code as operational mechanics, not IP.
R9 is local-only: "R9 es de Cochi" — multi-device sync is not a requirement at any phase. Cochi never deletes R9 without explicit confirmation.
Occidente/Asia naming deprecated in favor of personality-based tier names (Sigilosa/Afilada for Asun, Centinela/Terminator for Cochi). Occidente/Asia labels retired from user-facing copy.
Asun and Cochi are complementary "two arms": Asun (Sigilosa/Afilada) thinks and analyzes with full filesystem access; Cochi (Centinela/Terminator) executes. Neither is subordinate.
onSave ref timing pattern: onSave={(data) => cochiSavePrefsRef.current?.(data)} — ref must be read at call time, not render time, to avoid null capture.
Desktop preferences are local JSON, not Supabase — no Supabase auth session in Tauri during Fase 0; service role key used where Supabase access is needed.
OpenCode vs. Cochi architectural difference: OpenCode has deeper iteration budgets and native filesystem tooling; Cochi's loop is intentionally bounded. Goal is not to depend on OpenCode long-term.
Tito's needsWebSearch() guard prevents Perplexity from being triggered for conversational/short messages — important cost control.
Rename decisions: R1/R2/R3 label renaming to opaque strings rejected — semantically meaningless without Supabase prompt context, creates internal confusion for no meaningful security gain.

Approach & patterns

NOCOD mode: Claude handles architecture decisions and produces /COCHI instruction blocks; Cochi executes all file system changes. Roberto executes SQL changes personally via the Supabase dashboard.
/COCHI instruction block format: Direct imperative commands to Cochi. Used for all code changes. For non-code content (SQL, Edge Function TypeScript), Roberto prefers receiving raw content blocks to paste directly.
Architecture freeze before code: Roberto freezes all decisions explicitly in structured lists before any code is generated. Tradeoffs and A/B options are presented before acting on ambiguous decisions.
Bridge documents: Session continuity maintained via Bridge documents (currently v14). Each session opens by establishing the Bridge as source of truth.
/COCHI confirmation protocol: A /COCHI block counts as full confirmation for all operations including destructive ones — no additional confirmation required.
Tauri build workflow (Windows/PowerShell): Roberto is on Windows; PowerShell syntax used for terminal commands. Two terminals required for npx tauri dev + npm run dev.
Communication style: Roberto communicates corrections directly and concisely. Prefers Claude to flag tradeoffs proactively. Uses callsigns "Maravilla" / "Signor Roberto."
